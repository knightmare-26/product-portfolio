How I work

A loop I try to run fast and cheaply before committing engineering time.

Frame the problem

Write the one-pager first. If I can't state the user, the pain, and how we'd know it's fixed, it's not ready to build. This alone cut clarification cycles with my engineers by about half.

Listen at scale, not anecdotally

Lightweight user research plus a feedback pipeline that aggregates reports by theme and frequency — so prioritization runs on a pattern, not the last loud request.

Test before you build

Prototype in Figma, beta-test early builds, probe AI features with real prompts and MCP integrations. The goal is a signal, not a launch.

Ship, measure, write it down

Define the metric before launch, track it on a live dashboard, and publish a short retro so the team keeps the learning.
