Full Case Study · Aera Technology · 2024
Eliminating Information Loss in Distributed Software Teams

How I diagnosed async communication failure modes in a US–India split team, designed the SIGNAL framework, and reduced engineering clarification cycles by ~50%.

STEP 01
Problem Discovery
Discovery

In distributed delivery across US and India time zones, async handoffs were creating a recurring pattern: engineers starting work on ambiguous tickets, re-asking clarifying questions, and reworking completed items.

  • Signal: Jira ticket comments showed repeated "can you clarify X?" patterns before dev could begin
  • User pain: Engineers losing 30–90 min per ambiguous ticket to back-and-forth
  • Business impact: Sprint velocity reduced, release dates slipping on discoverable issues
  • Research method: Lightweight interviews with engineers + retrospective pattern analysis
STEP 02
Goal & Success Metrics
Framing

North star: reduce the friction of async handoffs without adding documentation overhead that slows the team down.

  • Primary metric: Engineering clarification requests per sprint (baseline → target: –50%)
  • Leading indicator: % of tickets with acceptance criteria defined before dev starts
  • Guardrail: Ticket creation time must not increase materially (<10% overhead)
SIGNAL = Single source of truth · Intelligence automates documentation
Gate tickets before dev · No waiting async · Accountability per decision · Live visibility
STEP 03
Solution Exploration
Ideation

Generated three solution directions before committing:

  • Option A — Sync standups across timezones: Rejected. Sustainable cost too high for distributed team; creates meeting fatigue
  • Option B — Mandatory ticket template: Partially adopted. Not sufficient alone — people fill templates mechanically without thinking
  • Option C (chosen) — SIGNAL framework: A lightweight structured protocol that defines what must exist before a ticket enters dev, enforced at the gate, supported by AI-assisted documentation generation

Prioritisation rationale: highest impact-to-effort ratio (low calendar cost, high clarity gain), aligned to existing Jira workflow.

STEP 04
Design & Spec
Build

Designed the SIGNAL protocol and wrote the implementation spec covering:

  • Jira ticket gate checklist (6 criteria, must be checked before dev assignment)
  • AI-assisted documentation template using LLM to pre-populate context fields
  • Escalation path for ambiguous requirements that can't be resolved async
  • Accountability model: ticket author owns completeness; PM reviews at gate
STEP 05
Stakeholder Alignment
Execution

Socialised the framework across engineering, design, and business stakeholders. Key alignment moments:

  • Engineering team buy-in via retro session — surfaced shared frustration, made the framework feel engineer-led, not PM-imposed
  • Leadership visibility through updated sprint health dashboard (Power BI) tracking gate compliance rate as a new metric
  • Phased rollout: 1 team → 2 sprints → full adoption, with a rollback clause if overhead exceeded 10%
STEP 06
Results & Learnings
Impact

After implementation across 2+ sprint cycles:

  • ~50% reduction in engineering clarification requests per sprint
  • Gate compliance reached 85%+ within 3 sprints
  • Ticket creation overhead: negligible (engineers reported less than 5 mins added)
  • Key learning: The AI documentation assist was the highest-leverage addition — removing the "effort" of writing context unlocked compliance
  • What I'd do differently: Instrument baseline data earlier; started measuring mid-way which weakened the before/after story
