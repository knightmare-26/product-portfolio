Shif1 UP: Formula 1 analytics and race predictions

A full-stack F1 analytics platform that predicts qualifying, race and championship outcomes with machine-learning models. Every prediction is checked against the real result, and the whole thing runs on free hosting.

The problem

F1 fans have plenty of data, but almost nothing honest about how predictable a race is. I wanted predictions that show their own track record, on infrastructure that costs nothing to run.

In one place: 75 years of standings, session results, lap-by-lap race replays and ML predictions, with every prediction scored against what actually happened.

Results

Walk-forward backtest over 86 races, 2023–2026. Each race is scored by a model that never saw it.

~3.0qualifying places off per driver (baseline 3.5)
−31%Brier score on win chances
67%winners called (grid leader: 58%)
77%checkpoints naming the champion (baseline 71%)
  • Qualifying: about 3.0 places off per driver, better than predicting the championship order (3.5).
  • Race win chances: Brier score improved 31% (0.0376 → 0.0259), beating the historical starting-slot baseline. The predicted winner was right 67% of the time; picking the grid leader was right 58%.
  • Title race: named the eventual champion at 77% of checkpoints for drivers and 81% for constructors, against 71% for "the current leader wins".

What I built

Prediction engine

  • LightGBM lambdarank models for qualifying, sprint and race, blended with ridge regression because the two make different mistakes.
  • Inputs: rolling form, team form, circuit history, practice pace, season-to-date points, and preseason testing for new technical eras.
  • Explainable: every prediction shows per-driver factor contributions taken from the model's own split scores, with no SHAP library.

Calibrated odds

A Plackett-Luce simulation, fitted by likelihood on held-out races, turns model scores into win, pole and podium chances. Retirements are drawn from each driver's reliability record.

Championship simulator

Exact clinch and elimination maths (countback, sprint points), plus a 10,000-season Monte Carlo with shared per-car "form shocks".

Honest evaluation

  • A walk-forward backtest re-scores every race with a model that never saw it.
  • Results are compared with simple baselines: the starting grid and the championship order.
  • It rebuilds incrementally, refitting only what changed, whenever new results arrive.

Race replays

Stewards' penalties parsed from race-control messages, session weather, and a lap-by-lap replay on a live-timing-style board.

Self-maintaining data pipeline

  • Data comes from FastF1, Jolpica and OpenF1, with fallbacks when a source is locked during live sessions.
  • The API catches up on missed data when it starts.
  • A scheduled GitHub Actions job writes new results straight to the database every 15 minutes around race-weekend sessions, without ever waking the sleeping API server.
  • Open pages refresh themselves when new results land.

Resilient free-tier hosting

The API heals its own database connection, restores a paused Supabase project through Supabase's management API, and shows a wake-up screen while it does.

Kept honest

Features that didn't measurably help were tested and dropped: weather, teammate deltas, street-circuit flags and era resets. A feature stays only if the backtest says it earns its place.

Stack & engineering

  • Frontend: React, TypeScript, Tailwind, Framer Motion
  • Backend: FastAPI (Python, async, WebSockets)
  • ML & data: LightGBM, scikit-learn, pandas
  • Storage: PostgreSQL (Supabase), Redis (Upstash)
  • Ops: GitHub Actions, Render

About 330 backend and 70 frontend tests, isolated from every production service. The UI is accessible and responsive, with reduced-motion support.
